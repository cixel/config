⏺ I have enough to design this. Here's the plan, then I'll explain a couple of
  things before implementing.

  ★ Insight ─────────────────────────────────────
  - hunk (npm name hunkdiff) is a Bun-compiled TypeScript app, not Go. Building
  from source means pulling Bun + a workspace's worth of npm deps; that's
  painful in Nix because Bun's lockfile isn't a first-class citizen of nixpkgs.
  Upstream already publishes self-contained prebuilt binaries per platform, so
  wrapping those in a tiny stdenv.mkDerivation is the path of least resistance
  and keeps trust where the project already places it (its own release
  pipeline).
  - On Linux, a Bun-compiled binary is a regular ELF that dynamically links
  libc/libstdc++. Nix's autoPatchelfHook rewrites the ELF interpreter and RPATH
  at install time so the binary finds glibc et al. inside the Nix store rather
  than /lib64/ld-linux-.... macOS binaries Just Work because Mach-O resolution
  happens through dyld against absolute system paths, not a baked-in
  interpreter.
  - The stdenv.hostPlatform.system → asset table pattern is the idiomatic way
  nixpkgs handles "different prebuilt for each platform" packages (see vscode,
  1password-cli, etc.). Throwing on unknown systems means a clear error rather
  than a confusing build failure if someone tries this on riscv64-linux.
  ─────────────────────────────────────────────────

  ★ Insight ─────────────────────────────────────
  - Notice the build output's fixupPhase: stdenv ran strip -S on the binary even
   though we did nothing to ask for it. That's stdenv's default and usually
  fine, but for some prebuilt binaries (notably ones with embedded payloads or
  codesigning) stripping can corrupt them. If hunk ever stops working after a
  rebuild, suspect dontStrip = true; as the fix.
  - The Linux variant will go through a different code path the first time
  anyone runs hms on alnitak-wsl/banjo/pi0/vm-aarch64: autoPatchelfHook will
  report which .so deps it had to resolve. If it complains about missing libs at
   that point, add them to buildInputs. Common Bun-runtime additions are zlib
  and openssl, but the prebuilt should be self-contained for those.
